# 示例：任務卡總結

本示例的來源是虛構的。來源是 3 張任務卡和一段迭代說明。

## 改寫前

> 本迭代需要對移動端登入模組進行最佳化處理，第三方登入暫不考慮。這裡的會話指登入成功後服務端保留的登入狀態。
>
> **Retry Login Requests on Weak Networks**（large，Bug）：針對弱網環境下登入請求經常超時、使用者體驗較差的問題，要做好重試機制的實現工作，重試不超過三次。
>
> **Notify Users When the Session Expires**（small，Bug）：會話過期後使用者無法感知，需要予以提示。
>
> **Keep the Password Field Above the Keyboard**（small，Bug）：密碼輸入框在部分機型上存在被鍵盤遮擋等問題。

不合格之處：

- 「進行最佳化處理」「做好……實現工作」「予以提示」是虛化動詞（R3）。
- 一句包含多個動作（R6）。
- 「需要」「要」詞義不固定（R11）。
- 「等問題」是開放式列舉（R17）。
- 「體驗較差」不是可檢查的結果。

## 改寫後

### 術語
- **會話**：登入成功後，服務端保留的登入狀態。

### 共同條件
- 只改移動端登入模組。
- 不做第三方登入。

### 1. 登入
**Retry Login Requests on Weak Networks**（large，Bug）
- 問題：網路訊號弱時，登入請求經常超時。
- 要做：
  - 登入請求超時時，自動重試。
  - 重試最多 3 次。

**Notify Users When the Session Expires**（small，Bug）
- 問題：會話過期後，應用不提示使用者。
- 要做：
  - 會話過期時，顯示提示。

**Keep the Password Field Above the Keyboard**（small，Bug）
- 問題：在部分機型上，鍵盤擋住密碼輸入框。
- 要做：
  - 鍵盤彈出時，密碼輸入框保持在鍵盤上方。

### 待確認
- 「部分機型」的具體型號清單。來源沒有列出。
- 第三張卡的「等問題」是否包含其他問題。來源沒有列出。
- 3 次重試都失敗後的行為。來源沒有規定。
- 會話過期提示的內容，以及使用者看到提示後的下一步。來源沒有規定。

## 說明

- 改寫後的每個事實都來自來源（R25）。標題、規模和型別保留來源的原文。
- 「重試最多 3 次」來自來源的「重試不超過三次」。來源沒有規定次數時，不得自行寫次數，必須把次數列入「待確認」。
- 來源沒有規定重試失敗後的行為，也沒有規定提示的內容。改寫不得自行補充，因此列入「待確認」。
- 「部分機型」和「等問題」在來源中沒有清單，同樣列入「待確認」。
- 「體驗較差」沒有可檢查的結果。改寫後刪除，只保留「經常超時」這個現象。
